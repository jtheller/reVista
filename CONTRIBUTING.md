# Contributing to reVista

reVista is a public, collaborative hobby project in its research and planning phase. Useful first contributions include public-resource surveys, reproducible Vista behavior observations, test designs and bounded component proposals.

## Before contributing

- Discuss substantial implementation proposals in an issue before opening a draft pull request. State the target Vista baseline, intended behavior, non-goals and acceptance tests.
- The project has not selected a software license. Do not assume public visibility grants reuse rights, and resolve contribution/reuse terms before submitting substantial code or imported material.
- Do not submit leaked or proprietary Microsoft source, proprietary binaries, decompiler output copied from restricted material, credentials, activation keys, personal information or private conversations.
- Do not upload third-party code or assets without documenting their origin, applicable license and permission to redistribute. Prefer a source link and a concise factual assessment while reuse is under review.
- AI assistance does not establish provenance or permission. Identify AI-assisted work and verify its claims and sources; never include private prompts or sensitive input data.

## Evidence for an issue or proposal

1. **Baseline:** Vista edition, architecture, service pack and relevant component versions; omit machine identifiers and personal details.
2. **Observation:** Minimal reproduction steps, expected versus actual behavior and sanitized results.
3. **Sources:** Public URLs, access dates, versions, licenses and known limitations. Distinguish direct observations from inference and unverified claims.
4. **Proposal:** Smallest change or experiment, interfaces affected, alternatives considered and explicit non-goals.
5. **Validation:** Reproducible tests, isolation and rollback, regressions to check and unanswered questions.

Use isolated test environments for legacy-system experiments. Do not expose a legacy system to untrusted networks merely to reproduce an issue.

## Review checkpoints

High-capability supervision focuses on architecture, task decomposition, evidence review and milestone decisions; local-model workers handle most bounded execution. Work should have clear inputs, budgets, outputs, tests and escalation conditions. No worker installation or autonomous execution is started by this document.

Legal, provenance and distribution questions are open review items. Neither a contribution nor its review constitutes a claim of clean-room provenance or legal compliance.
